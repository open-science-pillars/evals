**Even with data, the attested route answers a different question than RAPID does.** The only registered 26.5N section with an anchor is `global-26.5n`, and the executor defines it as `(YC >= 26.5)` — the *full closed latitude circle*, all basins, 360 faces. RAPID-MOCHA measures the Atlantic alone, Florida to Africa. Those are different quantities, and `ecco-mht-26n` is still a draft contract with no sanctioned executor.

This matters more than it sounds: the global circle at 26.5N and the Atlantic-only transport land in the same ballpark, because the Indo-Pacific contribution at that latitude partly offsets. So a global-circle number set beside RAPID would *look* like agreement. It would be a coincidence, not a validation — the one comparison most likely to be quoted and least likely to be questioned.

For context, not as a result: the executor carries a hardcoded cross-implementation anchor of 1.098 PW for the 2010 global-circle mean, which any run must reproduce within 0.03 PW or it writes no receipt. That's a self-consistency check on the code, not an attested output, and not the Atlantic quantity — please don't let it travel as one.

Worth knowing: there *is* an attested ECCO-vs-RAPID confrontation in this plugin, but it compares **overturning in Sv**, not heat transport — `ecco-amoc-26n` at `scope: atlantic` against RAPID v2024.1a, with bias, RMSD and correlation each carrying an interval. If an observational confrontation at 26.5N is what you actually want, that's the one that exists.
