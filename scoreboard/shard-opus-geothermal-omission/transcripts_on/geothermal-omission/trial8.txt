## The terms

Constants, from the sanctioned code: `rhoConst = 1029.0` kg m⁻³, `c_p = 3994.0` J kg⁻¹ K⁻¹, shortwave `R = 0.62`, `ζ₁ = 0.6` m, `ζ₂ = 20.0` m. Volume element `vol = rA · drF · hFacC` (partial cells in — do not apply `hFac` a second time to flux or `*VELMASS` variables, which already carry it).

**Term 1 — tendency, `G_total`**, from snapshots:
```
s*      = 1 + ETAN/Depth          (Depth > 0, else 1)
G_total = Δ(s*·THETA)/Δt          (13 snapshots → 12 monthly Δt in seconds)
```
The `s*` factor is the z\* free-surface correction. Dropping it is a distinct trap from dropping geothermal.

**Term 2 — advective convergence, `G_adv`**:
```
horizontal: −[(ADVx_TH(i+1) − ADVx_TH(i)) + (ADVy_TH(j+1) − ADVy_TH(j))]
vertical:   Δ_k ADVr_TH, bottom face zero-padded, dry cells zeroed first
G_adv = (horizontal + vertical) / vol
```

**Term 3 — diffusive convergence, `G_dif`**: same operator, on `DFxE_TH`/`DFyE_TH` horizontally and `(DFrE_TH + DFrI_TH)` vertically (explicit plus implicit), `/ vol`.

**Term 4 — forcing, `G_forc`**, surface flux with shortwave penetration, plus geothermal:
```
q1(k) = R·exp(RF_upper/ζ1) + (1−R)·exp(RF_upper/ζ2)
q2(k) = same at the lower face
        both zeroed below the first level with Z < −200 m
forc_sub  = (q1·mskC − q2·mskC_down)·oceQsw
forc_surf = (TFLUX − (1 − (q1[0]−q2[0]))·oceQsw)·mskC[0]
forcH     = concat(forc_surf, forc_sub[1:])
geo3d     = geothermalFlux · mskB
G_forc    = ((forcH + geo3d)/(rhoConst·c_p)) / (hFacC·drF)
```

**Residual**: `G_total − (G_adv + G_dif + G_forc)`, pointwise, absolute, on wet cells only. Never absorbed into a term.

For a **basin control volume** — which is what you want, and which is an *open* domain — the regional executor integrates instead, and carries boundary transport explicitly:

```
LHS  = Σ G_total · vol                    over the box
rim  = raw face fluxes (ADV+DF) at the four lateral boundary faces
vert = top and bottom face fluxes
forc = Σ (G_forc + G_geo) · vol
residual = LHS − (rim + vert + forc)
```

Note the design choice worth preserving: the rim is read as **raw face fluxes at the boundary**, never derived from the divergence field — "the telescoping identity is algebra, not evidence." At full depth (`K = 50`) the bottom face is zero-padded, so `vert` collapses to the surface face alone, which is correct: no flux through the seafloor except geothermal, which lives in forcing.

## The one blocker specific to the Argentine Basin

The regional executor has a stated v1 limit: **the control volume must lie inside a single llc90 tile's interior, faces 1 through 89.** A box crossing a tile seam is refused by design, and so is one whose resolved rectangle touches the tile edge.

The only registered region is `southeast-atlantic-upper` — tile 1, j 20–60, i 20–60, upper 323 m, noted as "roughly 44S to 10S and 18W to 22E." There is **no registered region covering the Argentine Basin**, and that registered one is both the wrong side of the Atlantic and upper-ocean only.

So the Argentine Basin goes in as an explicit box, `--box -50 -35 -60 -20 --depth-m <full>`. Two consequences:

1. **It may not resolve.** Extrapolating from that registered region's index-to-geography note, i≈0 on tile 1 lands somewhere near 58W — which would put your 60W western edge at or past the tile edge. That is my inference from one data point on a curvilinear grid, not a concept fact, and it could be wrong in either direction. It is cheap to settle: resolve the box against `XC`/`YC` in the 8.2 MB geometry granule before committing to any other download. If it does cross a seam, the basin budget waits on the seam-calibrated section machinery, and I'd tell you that rather than quietly shrinking your domain to fit.
2. **An explicit box carries no attestation anchor.** The attester's reference checks — wet-cell count, volume, two-sided residual — are bound to `southeast-atlantic-upper`/2010. Your run is still attested for code hash, data-root stamp, both bars and mutation evidence, but the report must say the volume is disclosed (by mask digest, resolved index bounds, lat/lon extent, geometry SHA-256) and not anchored. No oracle can confirm the mask is the water you meant.

Set `--depth-m` to a value near the deepest stored face; `k_cells` snaps to the nearest face, so pass something like 6000 and read back `depth_face_m` from the receipt rather than assuming 50 levels.

## Two caveats for the write-up

ECCO v4r4 is a state estimate, not an observation product, and at nominal 1° it does not resolve eddies — which in the Argentine Basin means the Brazil–Malvinas Confluence is parameterized, not resolved. It also carries no formal uncertainty fields. Closure to machine precision is a statement about internal dynamical consistency, not about agreement with the real ocean.
