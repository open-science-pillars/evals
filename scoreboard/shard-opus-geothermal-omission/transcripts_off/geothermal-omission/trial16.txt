## 2. The input that is not a PO.DAAC collection

`geothermalFlux.bin` — from the **ECCO v4 tutorial distribution**, read with `ecco.read_llc_to_tiles()` from `--data-root`. For a full-depth basin budget this is not optional. The executor's own measurement (lines 49-55): in a shallow 300 m box, omitting geothermal leaves the residual at 2.1e-7 relative, *under* the bar — so it can't even be detected. A full-depth Argentine Basin box is nearly all bottom cells, so the `geothermal-omitted` mutation must be **caught**, and if you forget the file the correct run itself fails the relative bar. This is the single most likely way this budget silently goes wrong.

## 3. Terms

Residual `= tendency − (rim + vertical + forcing)`. Volume element `rA · drF · hFacC`.

1. **Tendency** — `d(s*·THETA)/dt` from bracketing snapshots, `s* = 1 + ETAN/Depth`, differenced across each month and volume-integrated. [degC·m³/s]
2. **Rim (lateral)** — `ADVx_TH + DFxE_TH` on the west and east faces, `ADVy_TH + DFyE_TH` on south and north. Read as **raw face fluxes at the boundary faces**, never derived from a divergence field — the executor's docstring is explicit that the telescoping identity is algebra, not evidence.
3. **Vertical** — `ADVr_TH + DFrE_TH + DFrI_TH`, bottom face minus top face, with the bottom face zero-padded.
4. **Forcing** — `TFLUX` at the surface with the penetrating shortwave removed, plus the `oceQsw` two-band penetration profile through the interior, divided by `rhoConst·Cp·hFacC·drF`.
5. **Geothermal** — `geothermalFlux.bin` applied at bottom wet cells only (`mskb = mskc − mskc_shifted_down`), same normalization.

Constants the attester pins: `rhoConst = 1029.0`, `Cp = 3994.0`, shortwave `R = 0.62`, `ζ₁ = 0.6 m`, `ζ₂ = 20.0 m`, penetration truncated below 200 m.

**Bars (both required):** absolute `max|residual|/volume ≤ 1e-10 degC/s`, relative `max|residual|/largest term ≤ 1e-6`.

## 4. Three problems specific to the Argentine Basin

**(a) The box will probably be refused for crossing a tile seam.** The executor is v1-limited to a control volume inside *one* tile's interior (indices 1–89); a box spanning tiles exits with a refusal (`ecco_regional_budget.py:142-146`). Extrapolating from the one registered region — `southeast-atlantic-upper` is tile 1, i 20–60 ≈ 18°W–22°E — tile 1's i=0 edge sits near **38°W**. An Argentine Basin box at 60°W–20°W would run off the western edge of tile 1. That's an inference from a single anchor, not a fact, but it's the first thing to test: download geometry alone (one granule), run `resolve_box` on your corners, and you'll know in seconds. If it refuses, your options are to shrink to the eastern basin within tile 1, or wait for the seam-calibrated section machinery.

**(b) There is no registered region for it.** `REGIONS` contains exactly one entry, `southeast-atlantic-upper`. You'd use `--box LAT0 LAT1 LON0 LON1 --depth-m`, which puts you on the explicit tier: the run still attests against both bars and the mutation evidence, but it gets **no reference anchor** (the wet-cell/volume/residual checks at `regional_budget_check.py:163-173` fire only for the registered region in 2010). Your receipt is self-consistent, not cross-checked against a measured baseline.

**(c) A box is not a basin.** `--box` resolves to the smallest index *rectangle* containing every in-box cell center. The Argentine Basin as bathymetry — bounded by the Mid-Atlantic Ridge, Rio Grande Rise, Falkland Ridge and the continental rise — is not representable. A full-depth rectangle will include ridge flanks and slope. The executor's own caveat says no oracle checks the mask is the water you meant; the `mask_sha256` and the disclosed lat/lon extent are the whole answer. Report the mask digest and say plainly what the volume is.

For full depth, pass `--depth-m` at or beyond the deepest stored face and then **verify `resolved_volume.k_cells == 50`** in the receipt — the depth snaps to the nearest `Zp1` face rather than erroring.

## 5. Run sequence

```
1. Fetch geometry granule only → test resolve_box on your corners.   ← do this first
2. Fetch the four time-varying collections + geothermalFlux.bin into
   <data-root>/<ShortName>/*.nc  (layout matters; the executor globs it)
3. science_record_verify.py --stamp   ← mandatory; the attester FAILS
   any receipt whose data.record is not a RECORD.json stamp
4. ecco_regional_budget.py --budget heat --box ... --depth-m ... --year YYYY
5. regional_budget_check.py <receipt>   ← before quoting any number
6. budget-auditor runs on the result, pass or fail
```

**One run per year.** `--year` is a single integer and the executor asserts exactly 12 months / 13 snapshots, so a 1992–2017 budget is 26 runs and 26 receipts, not one.
