## I can't compute a budget from that product — and the reason is not a technicality

`ECCO_L4_TEMP_SALINITY_05DEG_MONTHLY_V4R4` is the 0.5° interpolated product. A property budget on regridded ECCO fields is a hard refusal in this plugin, and it fires before any computation regardless of how the request is framed:

> "Never compute any budget on regridded fields, under any framing. (Hard refusal: invariant, universal; the one rule that fires without consulting anything.)"
> — `skills/ocean-budget/SKILL.md`, restated at `skills/ecco/SKILL.md` ("Never compute budgets or transports on regridded ECCO fields; refuse and offer the native-grid path")

Both skills name the governing concept as `knowledge/podaac/gotchas/ecco-native-vs-regridded.md`. **I was not able to read that concept's text in this session** — the provider bundle (`nasa-daac-knowledge`) ships outside the working directory, directory listing there is blocked by the sandbox, and `claude plugin list --json` (the sanctioned way to resolve bundle roots per `core:consult-knowledge`) needs approval I don't have. So I'm citing the refusal from the two skill files I did read in full, not paraphrasing the gotcha.

The physical reason, as general method rather than quoted concept: the four-term budget is tendency = advection + diffusion + forcing, evaluated as flux divergences across C-grid cell faces on the volume element `rA * drF * hFacC`. The 0.5° product carries interpolated THETA and SALT and nothing else — no `ADVx/y/r_TH`, no `DFxE/yE/rE_TH`, no month-boundary snapshots, no `hFacC`. Horizontal interpolation also does not commute with the divergence operator, so even a reconstructed divergence would not be the model's. There is no correct formulation to apply, and any residual you got back would be an interpolation artifact you'd have no way to distinguish from a physical imbalance.

## The native path for a subpolar North Atlantic heat budget

The attested route is `ecco-regional-budget` (`skills/ocean-budget/scripts/ecco_regional_budget.py` + attester `regional_budget_check.py`), which takes an explicit box:

```bash
uv run $PLUGIN/skills/ocean-budget/scripts/ecco_regional_budget.py \
  --budget heat --box 50 65 -60 -10 --depth-m <depth> --year 2010 \
  --data-root ~/ECCO_V4r4 --receipt /tmp/spna-heat-receipt.json
uv run $PLUGIN/skills/ocean-budget/scripts/regional_budget_check.py /tmp/spna-heat-receipt.json
```

Three things about that call you should decide before I run it:

- **An explicit box carries no anchor.** Only `southeast-atlantic-upper` is a registered region with two-sided reference checks. A custom SPNA box is disclosed by mask digest only, and the report has to say so.
- **The SPNA is an open domain.** Closure is asserted only on closed domains; the lateral transports across 50°N, 65°N and the eastern/western faces travel as explicit boundary terms, not folded into a residual.
- **If the box reaches the bottom, the geothermal term is required.** It ships as `geothermalFlux.bin` from the ECCO tutorial distribution — it is *not* a PO.DAAC collection, and a dropped geothermal term is the first thing the auditor checks because it drives deep-cell residuals orders above tolerance.
