## I can't compute a budget from that product — and this is a hard refusal, not a preference

**Request as parsed:** heat budget, subpolar North Atlantic, from `ECCO_L4_TEMP_SALINITY_05DEG_MONTHLY_V4R4` (regridded 0.5° lat-lon, monthly).

The `ocean-budget` workflow refuses any property budget on regridded ECCO fields, citing gotcha `knowledge/podaac/gotchas/ecco-native-vs-regridded.md`. The rule fires before any computation, whatever the framing.

**Why, concretely.** The ECCO heat budget is a finite-volume identity on the LLC90 C-grid: the tendency equals the convergence of advective and diffusive face fluxes plus forcing, cell by cell, with partial cells carried in `hFacC` and the volume element `rA·drF·hFacC`. Interpolating to 0.5° destroys the flux-divergence identity that makes it close — there is no correct budget formulation on that grid. Independently of that, the 0.5° product carries only the state fields (`THETA`, `SALT`). Three of the four terms simply are not in the file you have: no `ADVx_TH`/`ADVy_TH`/`ADVr_TH`, no `DFxE_TH`/`DFyE_TH`/`DFrE_TH`/`DFrI_TH`, no `TFLUX`/`oceQsw`, and no month-boundary snapshots for the tendency. Anything I produced from it would be a heat-content difference with a residual absorbed into it, presented as a budget.

## The native path

The attested regional route is `ecco_regional_budget.py` (contract `ecco-regional-heat-budget`, attester `regional_budget_check.py`). Collections it needs, as the sanctioned code reads them:

| Purpose | Collection |
|---|---|
| Geometry (`rA`, `drF`, `hFacC`, `Depth`, `Z`, `Zp1`) | `ECCO_L4_GEOMETRY_LLC0090GRID_V4R4` |
| Advective + diffusive θ fluxes | `ECCO_L4_OCEAN_3D_TEMPERATURE_FLUX_LLC0090GRID_MONTHLY_V4R4` |
| Surface forcing (`TFLUX`, `oceQsw`) | `ECCO_L4_HEAT_FLUX_LLC0090GRID_MONTHLY_V4R4` |
| Tendency, 13 month-boundary snapshots | `ECCO_L4_TEMP_SALINITY_LLC0090GRID_SNAPSHOT_V4R4` |
| `ETAN` for the z* scale factor, snapshots | `ECCO_L4_SSH_LLC0090GRID_SNAPSHOT_V4R4` |

One input is **not** a PO.DAAC collection: `geothermalFlux.bin`, read from the data root and applied at the bottom wet cell (gotcha `knowledge/podaac/gotchas/ecco-geothermal-flux.md`). Omitting it is the first thing the auditor checks on a failing heat budget. It has to be staged into the tree alongside the granules.

Two things about the subpolar North Atlantic specifically:

- The only *registered* region is `southeast-atlantic-upper`. A subpolar box (say `--box 45 65 -60 -10 --depth-m ...`) runs as an explicit box: disclosed by mask digest, carrying no reference anchor, so the attester recomputes the bars from the results but cannot check it against a reference configuration. The report has to say that.
- It is an **open** domain. Domain-integrated closure is asserted only on closed domains, so the lateral boundary transports across the box faces travel explicitly in the result rather than being folded into a residual.

uv run $ROOT/skills/ocean-budget/scripts/regional_budget_check.py /tmp/spna-heat-receipt.json
